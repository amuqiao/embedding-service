Stage 0
阶段 0 · 探测先行

先搞清楚模型到底长什么样，再定 schema

StemSplitio/htdemucs-ft-onnx 的真实落地不是单个 htdemucs_ft.onnx，而是 4 个专家 ONNX 文件：htdemucs_ft_drums.onnx、htdemucs_ft_bass.onnx、htdemucs_ft_other.onnx、htdemucs_ft_vocals.onnx。仓库还提供 bag_infer.py 作为官方聚合推理参考。阶段 0 不再确认"是不是多文件"，而是把这 4 个文件的本地 I/O 签名、sha256、固定窗口长度和 bag 聚合口径记录下来。这一步不做，后面写 executor 和 timeout 预算就会继续沿用旧的单文件假设。

需要准备的依赖和环境

依赖用途安装方式（本地 macOS）
onnxruntime加载并探测 ONNX 模型的 I/O 签名uv add --optional audio-separation onnxruntime
huggingface_hub从 HF 拉取模型文件uv add --optional audio-separation huggingface_hub
soundfile后续阶段读写 wav，探测阶段不是必须，可以一起装uv add --optional audio-separation soundfile
libsndfile1soundfile 的系统依赖（macOS 用 Homebrew）brew install libsndfile
这些依赖按计划文档的决策放进 pyproject.toml 的 [project.optional-dependencies] extra（例如 audio-separation），不进 base 依赖——本地探测/POC 阶段用 uv sync --extra audio-separation 显式装。

探测脚本：确认真实 I/O 签名

probe_onnx_io.py
import hashlib
from pathlib import Path
import onnxruntime as ort

MODEL_DIR = Path(".data/models/htdemucs-ft")
EXPERT_FILES = {
    "drums": "htdemucs_ft_drums.onnx",
    "bass": "htdemucs_ft_bass.onnx",
    "other": "htdemucs_ft_other.onnx",
    "vocals": "htdemucs_ft_vocals.onnx",
}

def sha256_file(path):
    h = hashlib.sha256()
    with path.open("rb") as f:
        for block in iter(lambda: f.read(1024 * 1024), b""):
            h.update(block)
    return h.hexdigest()

for stem, filename in EXPERT_FILES.items():
    path = MODEL_DIR / filename
    print("==", stem, path, "==")
    print("sha256:", sha256_file(path))
    sess = ort.InferenceSession(path, providers=["CPUExecutionProvider"])
    print("providers available:", ort.get_available_providers())
    print("-- inputs --")
    for i in sess.get_inputs():
        print(" ", i.name, "shape=", i.shape, "dtype=", i.type)
    print("-- outputs --")
    for o in sess.get_outputs():
        print(" ", o.name, "shape=", o.shape, "dtype=", o.type)

for helper in ["bag_infer.py", "requirements.txt"]:
    print(helper, "exists=", (MODEL_DIR / helper).exists())

业务错误码

错误码触发场景
AUDIO_STEM_INPUT_INVALID非 44.1kHz / 非立体声 / 非白名单 content_type

executor 骨架（伪代码，实际实现时参照 poster_title_image/executor.py 的写法）

executor.py（骨架）
class AudioStemSeparationJob(JobExecutor):
    name = "audio_stem_separation"
    visibility = "demo"          # 借用 demo 的准入限制语义，见计划文档"开放决策"
    role = "root"
    timeout_seconds = 2400          # 目标音频时长 x 预估 CPU 推理倍率 + 余量
    retry_policy = JobRetryPolicy(business_execution=ExecutionRetryPolicy(max_attempts=1, ...))

    async def _execute(self, job, db):
        audio_bytes = download_and_verify(job)              # sha256 校验
        validate_sample_rate_and_channels(audio_bytes)     # 拒绝非 44.1kHz 立体声
        sessions = get_or_load_onnx_sessions()             # 模块级单例：4 个专家 session
        stems = segment_and_infer_bag(sessions, audio_bytes) # 分段 + 4专家推理 + 官方bag聚合 + overlap-add
        objects = write_stems_to_oss(job, stems)
        return {"stems": objects, "duration_ms": {...}, ...}
做完这一步应该得到：能通过 POST /jobs 提交一个 audio_stem_separation job，并且 schema/registry 测试通过——但这一步不要求已经跑通真实推理逻辑，真实推理逻辑建议先在下面"POC 脚本"里独立验证。
Stage 1 · Track B
主线 B · lease 窗口修复

让 job_type 声明的 timeout_seconds 真正生效

这是本次接入过程中发现的、独立于 htdemucs 本身的 job kernel 缺陷：JobExecutor.timeout_seconds 会被存进 JobAttempt.timeout_seconds 列，但运行中 attempt 的 lease 窗口只认全局 settings.job_stale_running_seconds（由 LLM 语义的 MODEL_CALL_TIMEOUT_SECONDS 派生），从不读这一列。

改动位置

文件方法改动
app/repositories/job_repo.pyclaim_attempt_for_execution()设置 lease_expires_at 前取 max(lease_seconds, attempt.timeout_seconds)
app/repositories/job_repo.pyheartbeat_attempt()同上

两处已经在同一次查询里把 JobAttempt（含 timeout_seconds）连同 Job 一并锁定读出，不需要新增查询、不改调用方签名、不新增配置项。

这条主线和主线 A 没有代码依赖，可以同时开工；唯一的软依赖是"用多大的 timeout_seconds 测试"要等主线 A 把估算值定下来。
残留风险：这只是让"声明超时"和"生效 lease"对齐，不是恢复了分段级周期续约。worker 进程若在推理中途真崩溃，stale 检测延迟会变成 2400 秒量级。OSS 写入和 callback 投递仍要靠仓库既有的幂等键机制兜底。

POC Reference

写 executor 之前，先用独立脚本验证模型本身能用

把分段推理逻辑先写成一个脱离 Job Kernel 的独立脚本，跑通之后再原样搬进 executor.py——这样调试模型问题（采样率、分段参数、拼接杂音）时不需要每次都走一遍 POST /jobs 全链路。

poc_separate.py · 独立分段推理脚本骨架
import numpy as np
import soundfile as sf
import onnxruntime as ort

SR = 44100
SEGMENT_SECONDS = 7.8
OVERLAP_RATIO = 0.25
MODEL_DIR = ".data/models/htdemucs-ft"
MODEL_FILES = {
    "drums": "htdemucs_ft_drums.onnx",
    "bass": "htdemucs_ft_bass.onnx",
    "other": "htdemucs_ft_other.onnx",
    "vocals": "htdemucs_ft_vocals.onnx",
}
STEMS = ["drums", "bass", "other", "vocals"]

def load_wav(path):
    wav, sr = sf.read(path, dtype="float32", always_2d=True)
    assert sr == SR, f"需要 44100Hz，实际 {sr}——先用 ffmpeg 转码"
    wav = wav.T
    assert wav.shape[0] == 2, "需要立体声"
    return wav

def get_or_load_onnx_sessions():
    providers = ort.get_available_providers()          # 自动探测，本机通常只有 CPU
    return {
        name: ort.InferenceSession(f"{MODEL_DIR}/{filename}", providers=providers)
        for name, filename in MODEL_FILES.items()
    }

def run_expert_bag(sessions, chunk):
    expert_outputs = {}
    mix = chunk[None]                          # (1, 2, 343980)
    for expert_name, session in sessions.items():
        in_name = session.get_inputs()[0].name
        y = session.run(None, {in_name: mix})[0]   # (1, 4, 2, 343980)
        expert_outputs[expert_name] = y[0]
    return aggregate_like_bag_infer(expert_outputs)

def aggregate_like_bag_infer(expert_outputs):
    # 这里必须移植官方 bag_infer.py 的聚合逻辑；不要用单个专家输出替代。
    raise NotImplementedError("按 StemSplitio/htdemucs-ft-onnx 的 bag_infer.py 实现")

def segment_and_infer_bag(sessions, wav):
    seg_len = int(SEGMENT_SECONDS * SR)
    stride = int(seg_len * (1 - OVERLAP_RATIO))
    T = wav.shape[-1]
    out = np.zeros((4, 2, T), dtype=np.float32)
    weight = np.zeros(T, dtype=np.float32)
    window = np.concatenate([
        np.linspace(0, 1, seg_len // 2, endpoint=False),
        np.linspace(1, 0, seg_len - seg_len // 2),
    ]).astype(np.float32)

    for start in range(0, T, stride):
        end = min(start + seg_len, T)
        chunk = wav[:, start:end]
        if chunk.shape[-1] < seg_len:
            chunk = np.pad(chunk, ((0, 0), (0, seg_len - chunk.shape[-1])))
        y = run_expert_bag(sessions, chunk)      # 每段跑 4 个专家，再按官方 bag 聚合
        n = end - start
        out[..., start:end] += y[..., :n] * window[:n]
        weight[start:end] += window[:n]
        if end >= T:
            break
    return out / np.maximum(weight, 1e-8)

if __name__ == "__main__":
    wav = load_wav("input.wav")
    sessions = get_or_load_onnx_sessions()
    stems = segment_and_infer_bag(sessions, wav)
    for name, s in zip(STEMS, stems):
        sf.write(f"out_{name}.wav", s.T, SR)
        print("saved", name)
这份骨架刻意把 aggregate_like_bag_infer() 留成显式待实现点：正式 POC/executor 必须移植官方 bag_infer.py 的聚合逻辑，不能把任意一个专家 session 的输出当作最终结果。阶段 0 的 model_asset.yaml 需要记录 4 个专家模型的实测 I/O 签名和 sha256。

这个脚本本身就是"数据构建到输出"最小闭环的验证工具：跑通它 == 证明模型、依赖、分段算法都没问题，再决定要不要把这份逻辑原样搬进 executor.py。
