## 一、生产可调维度

```
吞吐量
  并发 AI 调用数  = worker_pod 数 × WORKER_CONCURRENCY
  允入上限        = MAX_ACTIVE_JOBS（queued + running 总量，超限 503）
  DB 连接约束     = api_pod × (DB_POOL_SIZE + DB_MAX_OVERFLOW)
                  + worker_pod × WORKER_CONCURRENCY
                  ≤ PG max_connections(100)

超时
  L1 锚点         = MODEL_CALL_TIMEOUT_SECONDS（唯一需要设置的超时）
  L3/L4/L5       由代码从 L1 自动派生，不需配置
```

两个维度完全由 **env vars（单 pod 参数）+ pod 数量（水平扩展）** 控制，无需改代码。

## 二、Job 生命周期时序模型

```
提交
  → queued
      ↓ worker 领取
      如果 queued + celery_task_id=NULL 超过 JOB_ORPHAN_TIMEOUT_SECONDS(300s)
      → recovery 重新投递（孤儿恢复）

  → running（worker 开始 AI 调用）
      ↓
      t+0     asyncio.wait_for 开始计时（L1 = MODEL_CALL_TIMEOUT_SECONDS）
      t+L1    L1 截断 → job = failed(JOB_TIMEOUT) + 发 Callback ──────────────┐
      t+L1+300  Celery soft_time_limit → 软超时处理函数（清理收尾）              │
      t+L1+360  Celery time_limit → SIGKILL                                  │
      t+L1+960  job_stale_running_seconds → recovery 扫描阈值                 │
               （防止 recovery 误判刚被 SIGKILL 的 job）                        │
                                                                              ↓
  → terminal（success / failed / timeout）
      → Callback 投递
          单次超时 = CALLBACK_TIMEOUT_SECONDS(5s)
          最多尝试 CALLBACK_MAX_DELIVERY_ATTEMPTS(12) 次
          失败后 CALLBACK_RETRY_DELAY_SECONDS(300s) 后重试
          投递窗口 = 5 + 175 = 180s < 300s（保证同一 callback 不被两个 worker 争抢）
```

## 三、参数分类判断（当前状态）

| 参数                                     | 当前状态           | 分类理由                                               |
| ---------------------------------------- | ------------------ | ------------------------------------------------------ |
| `MODEL_CALL_TIMEOUT_SECONDS`             | ✅ `.env.example`  | 吞吐量/超时核心锚点，每个部署不同                      |
| `WORKER_CONCURRENCY`                     | ✅ `.env.example`  | per-pod 并发数，决定单 pod 吞吐量                      |
| `MAX_ACTIVE_JOBS`                        | ✅ `.env.example`  | 允入控制上限，防止系统过载                             |
| `DB_POOL_SIZE`                           | ✅ `.env.example`  | 容量方程主变量，需要跟 pod 数联动                      |
| `DB_MAX_OVERFLOW`                        | ✅ `.env.example`  | 容量方程第二项，和 pool_size 共同决定上限              |
| `DB_SSL`                                 | ✅ `.env.example`  | 本地 false / 生产 true，典型部署差异                   |
| `CALLBACK_TIMEOUT_SECONDS`               | ✅ `.env.example`  | 单次投递超时，影响 callback SLA                        |
| `CALLBACK_MAX_DELIVERY_ATTEMPTS`         | ✅ `.env.example`  | 最大投递次数，callback 可靠性策略                      |
| `CALLBACK_RETRY_DELAY_SECONDS`           | ✅ `.env.example`  | 重试间隔，且参与不变量校验                             |
| `CELERY_MAX_RETRIES`                     | ✅ `.env.example`  | 任务级重试策略，`.env.test` 用 3，是真实的环境差异决策 |
| `CELERY_RETRY_DELAY`                     | ✅ `.env.example`  | 与上面成对，仅在 CELERY_MAX_RETRIES > 0 时有意义       |
| `JOB_ORPHAN_TIMEOUT_SECONDS`             | ✅ `.env.example`  | 孤儿恢复边界，高延迟环境可能需要调大                   |
| `OSS_INPUT_MAX_BYTES`                    | ✅ `.env.example`  | 输入限制，业务规模决定                                 |
| `NOVEL_LOCALIZATION_CHUNKING_ENABLED`    | ✅ `.env.example`  | 执行模式开关                                           |
| `NOVEL_LOCALIZATION_SINGLE_MAX_CHARS`    | ✅ `.env.example`  | 单次执行文本上限，和 L1 配套调整                       |
| —                                        | —                  | —                                                      |
| `DB_POOL_RECYCLE` (1800)                 | 🔒 Settings 默认值 | 网络空闲超时，基础设施细节，极少调整                   |
| `OSS_SCHEME` ("https")                   | 🔒 Settings 默认值 | 几乎永远 https                                         |
| `OSS_ENDPOINT_STYLE` ("")                | 🔒 Settings 默认值 | 从 endpoint 组合自动推导，显式覆盖场景极少             |
| `CELERY_RESULT_EXPIRES` (86400)          | 🔒 Settings 默认值 | result backend 清理，内部基础设施                      |
| `JOB_RECOVERY_INTERVAL_SECONDS` (60)     | 🔒 Settings 默认值 | recovery loop 内部节拍，不影响业务可见行为             |
| `JOB_RECOVERY_BATCH_SIZE` (100)          | 🔒 Settings 默认值 | 内部批大小，微优化                                     |
| `JOB_RECOVERY_CALLBACK_BATCH_SIZE` (50)  | 🔒 Settings 默认值 | 内部批大小                                             |
| `NOVEL_LOCALIZATION_CHUNK_SIZE` (3000)   | 🔒 Settings 默认值 | 分块实现细节，非业务意图                               |
| `PROMPT_CONFIG_PATH`                     | 🔒 Settings 默认值 | 路径极少变化                                           |
| —                                        | —                  | —                                                      |

| `_CELERY_HARD_TIMEOUT_BUFFER` (60)       | ⚙️ 模块常量        | 结构不变量边距：SIGKILL 前收尾时间；不可覆盖           |
| `_JOB_STALE_RUNNING_BUFFER` (600)        | ⚙️ 模块常量        | 结构不变量边距：防误判 stale job；不可覆盖             |
| `_CALLBACK_DELIVERY_WINDOW_BUFFER` (175) | ⚙️ 模块常量        | 结构不变量边距：防多 worker 争 callback；不可覆盖      |
| `MODEL_CALL_MAX_RETRIES` (0)             | ⚙️ 代码硬编码      | AI 调用永不重试（避免重复扣费），不应成为可配置项      |
