## 一、访问与登录

容器发版平台需要在**办公室或使用 VPN 网络**下访问。

- **访问地址**：[http://kuboard.stardustworld.cn](http://kuboard.stardustworld.cn)（以下统称"容器发布平台"）
- 使用管理员提供的账号密码登录。

---

## 二、选择 Kubernetes 集群

当前有两个集群可选：

| 集群名称 | 用途 |
|---------|------|
| 美西生产集群 | 生产环境 |
| 美西测试集群 | 测试环境 |

平台根据当前登录账户的授权，显示全部或其中一个集群。单击对应集群可进入名称空间选择界面。

---

## 三、选择名称空间

同一个项目的服务通常部署在同一个名称空间下，例如 `public-css` 项目相关服务会在 `test-public-css` 或 `public-css` 名称空间中。

**操作步骤：**

1. 选择集群后进入名称空间选择界面。
2. 在左侧栏选择 **"使用 ServiceAccount kuboard-admin 扮演 xxx"**。
3. 在右侧栏寻找**绿色标记**的名称空间（绿色代表拥有访问权限）。

进入名称空间后，会到达该空间的**概要页**，可查看所有已部署的应用。

## 四、更新镜像版本

### 4.1 镜像的构建

接入容器发布时，项目的 `test`/`master` 分支会放置以下两个文件：

- `Dockerfile`
- `.gitlab-ci.yml`

当这两个分支有**提交变动**时，会自动触发 CI 打包镜像，并在**钉钉群**中发送通知。

- 通常触发后 **2–10 分钟**内会收到打包成功的镜像版本信息。
- 如未收到，可在 GitLab 控制台该项目的 **CI/CD → 流水线** 中查看具体原因。

### 4.2 镜像版本信息

镜像打包成功后，钉钉群会收到一条通知，包含以下信息：

| 字段 | 说明 |
|------|------|
| 项目名 | 构建的镜像所属项目 |
| 分支 | `test`（测试环境）或 `master`（生产环境） |
| 公网 docker 镜像版本 | 镜像包的公网地址与版本号 |
| 内网 docker 镜像版本 | 镜像包的内网地址与**版本号**（用于填入平台） |
| sha256 校验值 | 镜像完整性校验 |

> **规律**：测试环境对应 `test` 分支，生产环境对应 `master` 分支。

### 4.3 更新镜像版本

1. 在容器发布平台进入**目标名称空间概要页**。
2. 找到并点击需要更新的应用（部分项目使用中文备注，更直观）。
3. 在应用详情页点击 **"调整镜像版本"**。
4. 将 4.2 中获取的版本号粘贴填入，点击**确定**。

**启动状态说明：**

| 颜色 | 含义 |
|------|------|
| 🟢 绿色 | 启动成功，应用运行正常 |
| 🟠 橙色 | 启动失败，需查看日志和右侧事件信息诊断原因 |

## 五、配置管理

项目中需要修改的配置文件或脚本通常使用 **ConfigMap** 进行管理，支持在线修改。

- 部分配置修改后 **10–15 秒内**直接对应用生效。
- 部分配置修改后需要**重启应用**才能生效。
- 具体情况需咨询管理员。

### 5.1 修改配置

1. 进入名称空间后，在左侧菜单找到 **配置中心 → 配置字典**。
2. 在列表中找到需要修改的配置（配置较多时可询问管理员）。
3. 点击配置项进入详情界面，点击 **"编辑"** 进行修改。
4. 修改完毕后，依次点击 **"保存"** → **"应用"** 退出。

**需要重启时：** 直接在应用界面点击 **"重启"** 按钮即可。

## 六、日志查看与 shell 终端的使用

### 6.1 日志查看

在应用详情页，点击 **"追踪日志"**，会新启动一个窗口，持续打印该应用在控制台输出的日志信息。

### 6.2 登录 shell

在应用详情页，点击 **bash → sh** 可登录容器的 shell 终端。

**注意事项：**

> 不建议像在普通服务器中那样随意执行各种操作，原因如下：
>
> 1. **容器配置较低**：操作过重可能导致应用崩溃或触发 OOMKill。
> 2. **镜像较为轻量**：很多常用命令在容器内可能找不到。

**适合使用终端的场景：**

- 查看某个文件是否存在（直接使用界面上的**文件管理器**更便捷）
- 简单的调试操作
