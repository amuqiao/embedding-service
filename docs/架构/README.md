## 核心概念速记

### 三个基本事实

```
1️⃣ 无状态网关
   ├─ 每个 Job 独立执行，不维护编排逻辑
   ├─ 用户侧负责决策（如 step1 失败是否重跑）
   └─ 任何实例都能处理任何请求

2️⃣ 异步执行
   ├─ 立即返回 202 + job_id
   ├─ 后台 Celery 异步处理
   └─ 通过 Callback 和轮询获取结果

3️⃣ 三层流程
   ├─ step1_localize: 文化改写 (中文→中文)
   ├─ step2_review: 质量评估 (通过/建议)
   └─ step3_translate: 英文翻译 (中文→英文)
```

### 请求的生命周期

```
用户发起请求
    ↓
API 验证 (validate job_type, model_id, prompt structure)
    ↓
存储 Job (status=queued)
    ↓
投入 Celery 异步任务
    ↓
立即返回 202 + job_id ← 用户此时可以开始轮询
    ↓
异步执行
├─ 加载输入文本 (OSS)
├─ 调用 LLM (OpenAI API)
├─ 解析输出 (按格式标记提取)
├─ 保存结果 (OSS + DB)
└─ 发送 Callback (异步通知)
    ↓
Job 进入终态 (succeeded/failed)
    ↓
数据保留 24h，之后自动删除
```

### 常见问题速答

**Q: 为什么 system block 是空的？**  
A: 所有约束通过 user block 传达，这样用户完全控制提示词内容，没有隐藏逻辑。

**Q: 为什么必须支持 Callback？**  
A: LLM 调用可能耗时 30-60s，同步等待会超时。Callback 让用户侧主动监听完成事件。

**Q: 为什么没有 execution_mode 字段？**  
A: 简化了，不再支持自动分块。用户侧可以在提示词中指导模型处理长文本。

**Q: 如何处理超大文本？**  
A: 通过提示词指导模型如何处理。或者用户侧手工分块，多次调用。

**Q: Callback 失败了怎么办？**  
A: Callback 最多重试 3 次。失败不改变 Job 状态，用户可以通过轮询兜底查询。

**Q: 支持多语言吗？**  
A: 当前支持中→英，多语言是未来可能的扩展。

## 工程实践指南

### 调用流程最佳实践

```python
# ✅ 推荐方案
1. 创建 Job (POST /jobs)
2. 配置 Callback (后端接收通知)
3. 定时轮询备选 (GET /jobs/{job_id}, 频率 2s，最多 24h)
4. 在 Callback 中保存完整结果到业务库
5. 轮询作为容错兜底，不作为主要获取结果的方式

# ❌ 避免的方案
- 轮询超过 24h（数据会被自动删除）
- 完全依赖 Callback（网络不稳定时可能丢失）
- 频繁轮询（超过 2s，浪费资源）
- 存储 job_id 后很久才查询（可能已过期）
```

### 错误处理最佳实践

```python
# 创建 Job 时
if response.status_code == 422:
    # 输入验证失败，立即修复（不要重试）
    handle_validation_error(response.json())
elif response.status_code >= 500:
    # 服务端错误，指数退避重试
    retry_with_backoff()

# 查询 Job 时
if status == "failed":
    error_code = response["error"]["code"]
    if error_code in ["MODEL_CALL_FAILED", "MODEL_OUTPUT_INVALID"]:
        # 模型问题，可能需要调整提示词
        review_and_retry_with_better_prompt()
    elif error_code in ["OSS_FETCH_FAILED", "OSS_WRITE_FAILED"]:
        # 存储问题，确保权限和路径正确
        check_oss_config_and_retry()
    else:
        # 其他错误，询问用户
        escalate_to_support(error_code)

# 接收 Callback 时
if not verify_signature(signature):
    # 签名验证失败，拒绝请求
    return 401

if job_id already_processed:
    # 幂等去重
    return 200  # 不重复处理

save_result_to_db(result)
return 200  # 确保返回 2xx
```

### 提示词优化指南

```
1. 使用 GET /prompt-templates 获取默认模板
2. 理解每个 block 的作用：
   - system: (空，无需修改)
   - user: 核心方法论，控制模型行为
   - work_note: 上一步的反馈，引导迭代
3. 测试：
   - 先用简单输入验证格式是否正确
   - 再用真实小说数据测试效果
   - 根据输出质量迭代优化
4. 避免常见错误：
   - 提示词太长导致 token 超出（模型会拒绝）
   - 格式要求不明确导致解析失败
   - 对模型能力期望过高（某些 case 模型做不好）
```
