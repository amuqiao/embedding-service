# 小说本地化服务 - 所有可能性枚举

## 一、Job 类型维度

### 1.1 当前支持的 3 种 Job

| Job Type | 输入 | 处理 | 输出 | 应用场景 |
|---------|------|------|------|---------|
| `step1_localize` | 原文(CH) | 文化改写 | 本地化稿(CH) + 工作注释 | 初稿生成 |
| `step2_review` | 本地化稿(CH) | 质量审核 | 通过/建议修改 | 质量控制 |
| `step3_translate` | 本地化稿(CH) | 英文翻译 | 英文终稿(EN) | 多语言适配 |

### 1.2 可能的新增 Job 类型

```
拓展方向 1: 多语言支持
├─ step3_translate_es: 西班牙语翻译
├─ step3_translate_fr: 法语翻译
├─ step3_translate_de: 德语翻译
└─ step3_translate_{lang}: 其他语言

拓展方向 2: 细粒度处理
├─ step1_localize_character: 角色名和社交称谓转换
├─ step1_localize_setting: 场景和地理环境转换
├─ step1_localize_culture: 文化元素替换
└─ step1_localize_dialogue: 对话美国化

拓展方向 3: 增强能力
├─ step0_preprocess: 输入预处理（清理、格式化）
├─ step2_review_detail: 详细分项评估（名字、场景、文化等）
├─ step2_plagiarism_check: 抄袭检查
├─ step4_distribution: 多渠道适配（Wattpad/Harlequin/Kindle）
└─ step5_marketing: 营销文案生成

拓展方向 4: 批量处理
├─ batch_step1: 批量本地化（处理多篇文章）
└─ batch_pipeline: 批量流水线（多篇经过完整 3-step）
```

### 1.3 Job 组合模式

**单 Job 模式**（当前）：
```
一个请求 → 一个 Job → 一个结果
```

**链式组合模式**（用户侧实现）：
```
Job1(step1) → [用户审核] → Job2(step2) → [用户决策] 
  ├─ 通过: Job3(step3) → 完成
  └─ 失败: Job1(step1, 重做) → ...
```

**并行组合模式**（可能性）：
```
输入文本 → Job1(step1) ─┐
                       ├─ 合并 → Job3(step3)
         → Job1(step1, variant2) ┘
```

## 二、提示词维度

### 2.1 当前提示词配置

**step1_localize**:
- system: 空
- user: 完整本地化方法论 (角色、任务、执行流程、质量控制等)
- work_note: 上一步建议或初始空

**step2_review**:
- system: 空
- user: 校验规范 (5 个条件，2 个失败场景)
- work_note: 固定空

**step3_translate**:
- system: 空
- user: 翻译原则 (语言风格、美国化、人名处理等)
- work_note: 固定空

### 2.2 提示词变体

**按风格划分**：
```
正式风格 (当前)
  ├─ 角色设定
  ├─ 任务描述
  ├─ 执行流程
  ├─ 质量检查清单
  └─ 输出规范

精简风格 (可能)
  ├─ 1-2 句角色定义
  ├─ 3-5 个执行要点
  └─ 输出示例 (few-shot)

示例风格 (可能)
  ├─ 示例输入
  ├─ 示例输出
  └─ 反例说明
```

**按目标读者划分**：
```
对 LLM 的提示词 (当前)
  └─ 详细的执行指导

对人类编辑的 SOP (可能)
  └─ 更简洁的操作流程

对质量评估者的 Rubric (可能)
  └─ 评分标准和检查点
```

### 2.3 提示词动态化

```
固定提示词 (当前)
  └─ GET /prompt-templates 返回的 default_content

可定制提示词 (可能)
  ├─ 用户在 POST /jobs 时传入完整 prompt 内容
  ├─ 支持 runtime 覆盖 system/user blocks
  └─ 支持条件性 prompt (如根据文本长度调整方法论)

学习式提示词 (未来)
  └─ 根据历史结果优化 prompt，自动 A/B 测试
```

## 三、输入维度

### 3.1 当前输入格式

```json
{
  "source": {
    "oss": {
      "oss_key": "...",
      "oss_url": "...",
      "content_hash": "sha256:...",
      "content_type": "text/plain; charset=utf-8"
    }
  }
}
```

限制：
- ✓ 仅支持 OSS（不支持直接上传文本）
- ✓ 仅支持 UTF-8 文本
- ✓ 最大 5 MB

### 3.2 可能的输入扩展

```
格式扩展:
├─ 支持 HTML/Markdown 输入 (自动转纯文本)
├─ 支持 DOCX/PDF 输入 (需提前转文本)
└─ 支持流式分块输入 (用于超大文件)

来源扩展:
├─ 支持直接上传文本 (< 100KB)
├─ 支持 HTTP URL 拉取
├─ 支持 S3/GCS 等兼容存储
└─ 支持本地文件 (仅开发环境)

元数据扩展:
├─ 作者信息 (影响翻译风格)
├─ 原始语言 (不总是中文)
├─ 目标受众 (儿童/成人/专业)
├─ 文学体裁 (言情/科幻/悬疑)
└─ 时代背景 (现代/历史/未来)
```

## 四、输出维度

### 4.1 当前输出结构

```
artifacts: [
  {
    key: localized_text | review_summary | translated_text,
    type: text | work_note,
    label: 中文标签,
    storage: oss_object,  // 大文本
    content: "...",       // 短文本
    apply_mode: replace | append  // 仅 work_note
  }
],
signals: {
  passed: bool  // 仅 step2
}
```

### 4.2 可能的输出扩展

```
结构增强:
├─ metadata: 源数据保留 (字数、时间、质量评分)
├─ chunks: 分块信息 (哪些部分被修改)
├─ delta: 变更追踪 (原文 vs. 输出的 diff)
├─ confidence: 模型置信度 (0-1)
└─ edit_logs: 编辑建议 (具体改了什么)

内容增强:
├─ multilingual: 同时返回多语言版本
├─ audio: TTS 音频版本
├─ summary: 内容摘要
└─ keywords: 自动提取的关键词
```

## 五、错误场景维度

### 5.1 当前错误码

```
输入校验:
  ├─ INVALID_JOB_TYPE
  ├─ MODEL_NOT_AVAILABLE
  ├─ INVALID_INPUT
  └─ INPUT_TOO_LARGE

OSS 操作:
  ├─ OSS_OBJECT_NOT_FOUND
  ├─ OSS_FETCH_FAILED
  ├─ OSS_WRITE_FAILED
  └─ INPUT_HASH_MISMATCH

模型调用:
  ├─ MODEL_CALL_FAILED
  ├─ MODEL_OUTPUT_INVALID
  └─ JOB_TIMEOUT

业务错误:
  ├─ JOB_NOT_FOUND
  └─ JOB_ALREADY_CANCELED
```

### 5.2 可能的新增错误

```
资源限制:
  ├─ RATE_LIMIT_EXCEEDED: 请求过于频繁
  ├─ QUOTA_EXCEEDED: 用户配额已用尽
  └─ MODEL_CAPACITY_FULL: 模型服务满载

业务逻辑:
  ├─ INVALID_PROMPT_BLOCKS: prompt 结构不符
  ├─ WORK_NOTE_CONFLICT: work_note 与当前状态冲突
  ├─ DUPLICATE_JOB: 检测到重复提交
  └─ PREREQUISITE_NOT_MET: 前置条件未满足 (如 step2 需要 step1 结果)

集成错误:
  ├─ CALLBACK_VALIDATION_FAILED: callback URL 不可达
  ├─ CALLBACK_REJECTED: callback 返回非 2xx
  └─ AUDIT_FAILED: 内容审计失败 (可能性)
```

## 七、可观测性维度

### 7.1 当前的可观测能力

```
✓ Job 生命周期追踪 (queued/running/succeeded/failed)
✓ 进度百分比 (0-100)
✓ 错误码和信息
✓ 时间戳 (created/started/finished)
✗ 模型 token 消耗
✗ 成本追踪
✗ 性能分析
```

### 7.2 可能的监控增强

```
性能指标:
├─ latency: 端到端耗时
├─ tokens_used: input/output token 数
├─ cost: 模型调用成本
├─ retry_count: 重试次数
└─ callback_latency: 通知延迟

质量指标:
├─ success_rate: Job 成功率
├─ review_pass_rate: 校验通过率
├─ model_reliability: 模型稳定性
└─ user_satisfaction: 用户反馈评分

流量指标:
├─ requests_per_minute
├─ concurrent_jobs
├─ queue_depth
└─ model_utilization
```

## 八、部署维度

### 8.1 当前部署模式

```
local: 宿主机 API + Worker，Docker 依赖
compose-deps: 仅 Docker 依赖，API/Worker 宿主机
compose-full: 全 Docker 编排
```

### 8.2 可能的扩展部署

```
水平扩展:
├─ 多个 API 实例 (负载均衡)
├─ 多个 Worker 实例 (Celery 集群)
└─ Worker 按 job_type 分组 (step1/2/3 分开)

地理扩展:
├─ 多个区域副本 (低延迟)
├─ 跨地域 Callback (地区合规)
└─ CDN 存储同步 (加速读写)

集成扩展:
├─ K8s 部署 (云原生)
├─ 无服务器 (AWS Lambda/Google Cloud Run)
└─ 边缘部署 (模型量化后的轻量化版本)
```

## 九、集成维度

### 9.1 当前的集成边界

```
输入端:
  ← OSS (Aliyun/本地存储)
  ← HTTP 请求验证

处理端:
  → OpenAI API
  → Redis (Celery broker)
  → PostgreSQL (Job 状态)

  → OSS (结果存储)
```

```
下游系统:
├─ 出版系统 - 接收终稿
```

## 十、业务模式维度

### 10.1 当前的使用模式

```
严格序列: Step1 → (审查) → Step2 → (决策) → Step3
  └─ 适合: 正式出版、质量优先

快速流程: Step1 → Step3 (跳过 Step2)
  └─ 适合: 内部预览、草稿测试

迭代改进: Step1 → Step2 (不通过) → Step1 (重做) → ...
  └─ 适合: 持续优化、反复打磨
```

### 10.2 可能的业务扩展

```
按客户类型:
├─ 出版社: 审核严格 (需要 step2)
├─ 自出版: 快速上线 (跳过 step2)
├─ 研究机构: 需要可追溯 (完整审计日志)
└─ AI 训练: 批量处理 (并行加速)

按使用频率:
├─ 按次计费 (当前)
├─ 包月订阅 (固定 quota)
├─ 按用量计费 (token/字符)
└─ 混合定价 (免费额度 + 超额付费)

按 SLA 等级:
├─ 标准: 24h 内完成，重试 3 次
├─ 加速: 1h 内完成，优先级队列
└─ 保障: 99.9% 可用，支持热备
```

## 总结：可能性空间维度

| 维度 | 当前状态 | 可能的 Level 1 扩展 | 可能的 Level 2 扩展 |
|------|---------|-------------------|-------------------|
| Job 类型 | 3 种 | +3~5 种 (多语言、新流程) | +10+ 种 (细粒度、新域) |
| 提示词 | 固定 | 可定制、动态 | AI 生成、学习优化 |
| 输入 | OSS 文本 | 多格式、多来源、元数据 | 流式、实时、交互式 |
| 输出 | 基础 artifacts | 分块、diff、置信度 | 多模态、多语言、动态调整 |
| 模型 | OpenAI | 多厂商、专用模型 | 本地部署、蒸馏量化 |
| 监控 | 基础指标 | 成本、质量、性能 | 自适应优化、预警 |
| 部署 | 单实例 | 集群、K8s、无服务器 | 多地域、边缘计算 |
| 集成 | 独立服务 | CMS/TMS 连接 | 完整内容生产流 |
