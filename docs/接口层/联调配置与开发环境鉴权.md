# 联调配置与开发环境鉴权

本文说明 CPP、RS 或前端调试工具如何访问开发环境接口，以及调用 Mock 接口时需要携带的鉴权信息。

## 开发环境

开发环境基础地址：

```text
http://47.119.149.179
```

Swagger UI：

```text
http://47.119.149.179/docs
```

OpenAPI JSON：

```text
http://47.119.149.179/openapi.json
```

## 鉴权方式

除 `/health` 和 `/healthz` 外，接口请求都需要服务间 Bearer 鉴权。

调用方请求时必须携带：

```http
Authorization: Bearer <dev-service-api-key>
X-AI-Service-Caller-ID: <caller>
```

字段说明：

| Header | 必需性 | 说明 |
| --- | --- | --- |
| `Authorization` | 必需 | 使用开发环境约定的 `SERVICE_API_KEY`，格式为 `Bearer <token>`。 |
| `X-AI-Service-Caller-ID` | 建议必传 | 调用方标识。CPP 传 `cpp`，RS 传 `rs`。 |

`X-AI-Service-Caller-ID` 不由服务端环境变量配置，由调用方每次请求传入。服务端在未传该 header 时会按 `default` 处理，但联调时不建议省略。

开发环境 token 不写入仓库文档。请从开发环境配置、部署平台或团队私有渠道获取。

## Swagger UI 使用

打开：

```text
http://47.119.149.179/docs
```

在页面右上角点击 `Authorize`，填入开发环境 `SERVICE_API_KEY` 的 token 本体。

注意：

- Swagger UI 的 `Authorize` 输入框只填 token，不要手动加 `Bearer `。
- `X-AI-Service-Caller-ID` 仍需要在接口的 header 参数位置填写。
- 如果页面看不到 Mock 接口，先确认访问的是开发环境最新实例，并刷新浏览器缓存。

## Mock 接口入口

Mock 接口按调用方拆成两组。

CPP 短剧打标 Mock：

```http
POST /api/v1/mock/cpp/ai-jobs/jobs
GET  /api/v1/mock/cpp/ai-jobs/jobs/{job_id}
```

RS 标签体系翻译 Mock：

```http
POST /api/v1/mock/rs/ai-jobs/jobs
GET  /api/v1/mock/rs/ai-jobs/jobs/{job_id}
```

旧路径不再作为对外 Mock 接口：

```http
POST /api/v1/mock/ai-jobs/jobs
GET  /api/v1/mock/tag-schemas/default
POST /api/v1/mock/ai-tag-results
```

## CPP Mock 调用示例

创建 CPP Mock Job：

```bash
curl -sS -X POST "http://47.119.149.179/api/v1/mock/cpp/ai-jobs/jobs" \
  -H "Authorization: Bearer <dev-service-api-key>" \
  -H "X-AI-Service-Caller-ID: cpp" \
  -H "Content-Type: application/json" \
  -d '{
    "client_request_id": "cpp:204200150000004872:initial:20260615",
    "job_type": "short_drama.tagging.initial",
    "job_params": {
      "t_book_id": "204200150000004872",
      "work_context": {
        "title": "Acting for Real-He Fell First",
        "subtitle_language": "en",
        "series_structure": "continuous_series",
        "episode_count": 80
      },
      "assets": [
        {
          "asset_type": "subtitle_srt",
          "episode_no": 1,
          "format": "srt",
          "text": "1\n00:00:01,000 --> 00:00:03,000\nI will not let them decide my life."
        }
      ]
    }
  }'
```

创建响应会返回 `status_url`。使用该路径查询：

```bash
curl -sS "http://47.119.149.179/api/v1/mock/cpp/ai-jobs/jobs/<job_id>" \
  -H "Authorization: Bearer <dev-service-api-key>" \
  -H "X-AI-Service-Caller-ID: cpp"
```

CPP Mock 成功终态的 `result` 固定为 `null`，与 CPP 正式接口保持一致。模拟打标摘要放在 `metadata.mock_tagging` 中，便于联调检查。

## RS Mock 调用示例

创建 RS Mock Job：

```bash
curl -sS -X POST "http://47.119.149.179/api/v1/mock/rs/ai-jobs/jobs" \
  -H "Authorization: Bearer <dev-service-api-key>" \
  -H "X-AI-Service-Caller-ID: rs" \
  -H "Content-Type: application/json" \
  -d '{
    "client_request_id": "rs:tag-schema-default:en,es,pt",
    "job_type": "short_drama.tag_schema.translation",
    "job_params": {
      "source_language": "zh",
      "target_languages": ["en", "es", "pt"],
      "source_schema": {
        "categories": []
      },
      "source_mutual_exclusion_rules": []
    }
  }'
```

使用创建响应中的 `status_url` 查询：

```bash
curl -sS "http://47.119.149.179/api/v1/mock/rs/ai-jobs/jobs/<job_id>" \
  -H "Authorization: Bearer <dev-service-api-key>" \
  -H "X-AI-Service-Caller-ID: rs"
```

RS Mock 成功终态会在 `result.artifacts` 返回：

| artifact key | 内容 |
| --- | --- |
| `translated_schemas` | `en`、`es`、`pt` 三套翻译后的标签结构体。 |
| `mutual_exclusion_rules` | 互斥规则列表，使用 `label_id` 和 `mutex_label_ids`。 |

## 状态模拟

查询接口支持用 `status` query 参数模拟不同状态：

```bash
curl -sS "http://47.119.149.179/api/v1/mock/cpp/ai-jobs/jobs/<job_id>?status=running" \
  -H "Authorization: Bearer <dev-service-api-key>" \
  -H "X-AI-Service-Caller-ID: cpp"

curl -sS "http://47.119.149.179/api/v1/mock/rs/ai-jobs/jobs/<job_id>?status=failed" \
  -H "Authorization: Bearer <dev-service-api-key>" \
  -H "X-AI-Service-Caller-ID: rs"
```

允许值：

| status | 说明 |
| --- | --- |
| `queued` | 模拟已接单、等待执行。 |
| `running` | 模拟执行中。 |
| `succeeded` | 模拟成功终态；默认值。 |
| `failed` | 模拟失败终态。 |

## 参数校验

Mock 接口会做基础校验：

| 校验项 | 失败表现 |
| --- | --- |
| 缺少或错误的 `Authorization` | 返回 `UNAUTHORIZED`。 |
| `job_type` 与路径不匹配 | 返回 `INVALID_JOB_TYPE`。 |
| `job_id` 不是 UUID | 返回 `INVALID_INPUT`。 |
| `status` 不在允许枚举内 | 返回 `INVALID_INPUT`。 |
| 使用已删除的旧 Mock 路径 | 返回 `404`。 |

`client_request_id` 是可选字段。调用方可以不传，不传时响应中为 `null`；联调和真实业务建议传稳定业务幂等键，方便排查和重试。

Mock 接口不会执行真实数据库任务、Celery 任务、模型调用或 RS 写入，也不会深度校验 `job_params` 的业务完整性。
